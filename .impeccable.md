## Design Context

### Users
Staff at NoaDentLab, a dental laboratory, using the app daily on desktop (occasionally tablet) to generate and manage delivery notes (albaranes) for dental prosthetics sent to clinics. Users are lab technicians/admin staff, not designers — they need speed and clarity while filling repetitive forms (patient data, product lines, prices) under light time pressure. Secondary audience: the dentist/clinic receiving the printed PDF.

### Brand Personality
Precise, trustworthy, unfussy — professional B2B lab tooling. Trilingual context (Dutch date fields, Catalan/Spanish UI) reflects a small, real business.

### Aesthetic Direction
**IMPORTANT — this is NOT a redesign.** The user was shown 3 bold alternative visual directions (editorial serif, dark console, soft rounded studio) and explicitly rejected all three, asking to keep the existing navy/teal Tailwind interface as-is. The current task is **incremental frontend quality improvement**: polish consistency, add purposeful motion/interaction where currently absent, improve UX clarity, and fix technical quality issues (accessibility, responsive, theming) — all while preserving the current navy/teal look, layout structure, and overall visual identity. Do not change the color palette, do not introduce a new type system, do not restructure navigation. No new npm dependencies unless clearly justified and lightweight (prefer plain CSS/Tailwind transitions over adding animation libraries).

### Design Principles
1. Preserve the existing navy/teal palette (`--navy`, `--navy-deep`, `--teal`, `--ink`, `--muted`, `--paper`, `--line`) and current layout/structure — improvements must be additive/corrective, not a new aesthetic.
2. Consolidate the repeated-but-uncentralized Tailwind utility strings (card, button, input, table-row patterns already duplicated across ~10 files) into consistent, reusable treatment — reduces drift without changing the look.
3. Motion should be purposeful and subtle: hover/focus/press feedback, loading states, transitions on add/remove of table rows — using CSS transitions, not a new animation library.
4. Accessibility matters: this is a real daily-use business tool, not a marketing site — fix contrast, focus states, form labels, touch targets, semantic HTML.
5. Trilingual labels (Dutch date fields, Catalan/Spanish UI copy) must remain legible and unchanged in meaning.
